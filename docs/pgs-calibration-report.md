## 2. D 分布(829,300 个候选位置观测)

| 分位 | 值 |
|---|---|
| P50 | 0.0027 |
| P75 | 0.0098 |
| **P85(规范 θ_D 落点)** | **0.0203** |
| **P90(q=10% 门率对应)** | **0.0338** |
| P95 | 0.0721 |
| P99 | 0.3033 |
| mean | 0.0187(hist_max 6.25)|

**⚠ 对 v1 读数的修正(重要)**:v1(64 桶)报 P85≈0.0866、P95≈0.096,并得出
"CDF 在阈值附近极陡、P85→P95 只差 0.01、固定阈值不可辨"的结论。**这全部是
桶分辨率伪影**:64 桶下桶宽 = 6.25/64 ≈ 0.098,比真实 P95 还大——P95 以下全部
质量挤在第一个桶里,分位数读数 = 首桶内线性插值,系统性高估约 4×。
2048 桶(桶宽 0.003)下的真实结构:P85=0.020 → P95=0.072(3.5×)→ P99=0.30,
尾部拉得很开。**含义:D 门的阈值可辨识性比 v1 结论好得多;但自适应门控仍然
必要(理由是训练中策略漂移使分布整体移动,不是可辨识性)。**

## 3. ℓ 观测(55.7M 个,窗口 ±12)

- 方向:lift(ℓ>0)52.8% / suppress(ℓ<0)47.2% —— 教师-学生分歧双向基本对称,轻微偏抬升。

  设计预期 10-25%,实测低一个量级 ⇒ **c=2.5 维持**(截断几乎不激活,ℓ̃≈ℓ,

  走单侧鲁棒代入的占比。v1 约 10%,本次 16%——非小量,已列入给 CD-010 的观察项。

## 5. 训练侧结论

- **sp=2 修复 OOM 实证**:三次 update 全过(step3 批含 32,704 token 满预算轨迹,
  v1 在同型批上 OOM)。正式 run 配置定型:sp=2 + gpu_mem 0.6。
  (原拟第三道防御 `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` 已撤回:
  与 vLLM CuMemAllocator 内存池不兼容,worker 启动即 assert 拒绝——pgs_base
  首启 10 分钟崩溃实测,pytorch#147851;launcher 已删并留注释防回归。)
- 3 步(门关=纯 GRPO)后 val:**33.9%**(seen 33.6 / unseen 34.3,截断 3/274);
  同 ckpt 训练前 32.2% ⇒ +1.7pp,在 val greedy ±5pp 噪声带内,模型未受损。
  同 ckpt greedy 读数集:31.8(C3)/ 32.2 / 33.9 —— 跨 run 噪声带宽 ≈2pp 的第三个样本点。
- 退出时 1 条 DataLoader worker SIGKILL 报错为 epoch 预取竞态噪声(dmesg 无当日
  OOM killer 记录;val 274/274 与 swanlab 收尾均在其后正常完成)。
