## 一、2510.19178 — Imbalanced Gradients in RL Post-Training of Multi-Task LLMs

Meta AI / Cornell,2025-10-26,17 页。**纯诊断论文,不提供任何修正方案**(Limitations 自述:"how to design new approaches to mitigate them remains unclear")。

### 1.1 机理与证据(§2–§4)

设置:Qwen2.5-3B/7B、Llama-3.2-3B,RLVR + GRPO,verl 框架(App C)。两组任务:多领域(Code / Countdown / MATH / FinQA)与单领域数学(DeepScaleR / MATH / Arithmetic)。
**关键设计:按等概率从各任务采样,而非按数据集大小混合**,以排除数据量带来的天然偏置(§2)。

- **失衡幅度**(Fig 1 左列):多领域中 Code 的**平方**梯度范数最高达 MATH 的 **15×**;单领域中 Arithmetic 达其余任务的 **33×**。等权混合 `ḡ = (1/M)Σ g_i` 实际退化为 `ḡ ≈ (1/M)Σ_{i∈I} g_i`,I 为大梯度任务集。换算成学习率视角:√33 ≈ **5.7×**,即 Arithmetic 相当于被用 5.7 倍学习率训练(§2 末)。

- **大梯度 ≠ 大学习增益**(§3.1):定义

  ```
  Gain(t) := (1/s)·Σ_{i=1..s} R_{t+i} − (1/s)·Σ_{i=1..s} R_{t−i}
  ```

  s 为平滑窗口(多领域 s=75、单领域 s=25,见 App C 绘图细节)。Fig 1 中列:Code 梯度最大但增益**最低**;Arithmetic 有 33× 梯度但训练过半后增益最低。

- **反证实验**(§3.2):梯度正比采样 `p_i = exp(‖g_i‖/η) / Σ_j exp(‖g_j‖/η)`,并下截断在 `p_i ≥ 0.1`。Table 1:确实抬高了大梯度任务的分数,但**平均分下降**——Qwen-3B 多领域 52.37→50.46、Llama-3B 46.62→46.12、Qwen-7B 61.97→60.48。Table 3 温度扫描 η ∈ {0.1, 0.01, 0.001}:η ≥ 0.1 与均匀采样几乎等价,温度越低平均越差,单调劣化。

- **失衡无法被任何训练统计量解释**(§4):
  - *优势值*:由 `‖∇J‖₂ ≤ E[|A^π(s,a)|·‖∇log π_θ(a|s)‖₂]`(Jensen)本应是好代理。Fig 2 散点:|A| 在**任务内**是合理代理,**跨任务失效**(同样 |A| 下 MATH 梯度远小于 FinQA)。
  - *训练 reward / 难度*:无一致跨任务规律。文中明确点出极端情形:准确率趋近 0% 或 100% 时 `A^π → 0`,由策略梯度定理期望梯度也 → 0(即"全对/全错组无信号"的机理陈述)。
  - *长度*:§4 原文——"In principle, it should not [affect gradient magnitude], because the policy-gradient loss is **averaged over tokens** and is therefore expected to be **invariant to sequence length**"。Fig 3 实测:prompt 长度(Code 553.2 / Countdown 164.5 / MATH 168.6 / FinQA 1161.9;DSR 173.1 / MATH 168.6 / Arithmetic 105.4)与梯度幅度无有意义相关;FinQA 长 prompt 大梯度,但 Arithmetic 最短 prompt 也最大梯度;response 长度曲线亦无关联。

- **理论解释**(App B):β-光滑给出 `f(x) − min f ≥ (1/2β)‖∇f(x)‖²`(式 1),μ-PL 给出 `(1/2)‖∇f‖² ≥ μ(f(x) − min f)`(式 2),合并得

  ```
  2μ  ≤  ‖∇f(x)‖² / (f(x) − min f)  ≤  2β
  ```

  所以"平方梯度范数 ∝ 次优间隙(→ ∝ 学习增益)"只在**单任务内**成立;跨任务因每个任务有各自的 β 与 μ 而破裂。这是"跨任务梯度不可比"的正式来源。

### 1.2 唯一可移植的算法资产:无偏平方梯度范数估计(App C.1)

朴素估计有偏:`E[‖ĝ‖²] = ‖g‖² + (1/B)·Tr(Σ)`,LLM 参数量巨大使该方差项不可忽略。修正法——把 batch 对半拆:

```
ĝ₁ = (2/B)·Σ_{i=1..B/2} X_i ,  ĝ₂ = (2/B)·Σ_{i=B/2+1..B} X_i
‖g‖²̂ = ⟨ĝ₁, ĝ₂⟩            (两半独立且各自无偏 ⇒ E[⟨ĝ₁,ĝ₂⟩] = ‖g‖²)
‖ĝ‖   = sqrt( max(‖g‖²̂, 0) )   (交叉积不保证非负,故截断)
```

其中 `X := ∇_θ log π_θ(a|s)·A^π(s,a)`。
**成本控制:只用最后一个 attention block 的梯度做全模型代理**;App D.1 Fig 4 验证第 36 / 18 / 1 块尺度可比、主导关系一致(前中层方差更大)。跟踪值再取 EMA 0.95。

### 1.3 超参(Table 2,全实验共用)

batch 128 · rollouts/prompt 16 · max prompt 2048 · max response 4096 · lr 5e-7 · KL 系数 1e-3 · entropy 系数 1e-3 · grad clip 1.0 · clip ratio 0.2;A100;多领域跑 300 步、单领域 100 步。绘图:平方梯度范数 EMA 0.9,reward 平滑 0.7。

### 1.4 局限

**自述**:只覆盖 RL 后训练阶段(pretrain / SFT 是否同样失衡未知);虽遍查训练统计量仍**无法解释**失衡为何产生;只报告观察、不给方法。

**我补充的范围性硬伤**:**它的四个任务全部使用同一种 loss 形式(GRPO)**,所以它的"跨任务梯度失衡"是同构目标下的任务异质性,与我们"dense token 级 OPD vs 稀疏轨迹级 PG"的**跨 loss 类型**失衡不是同一现象——后者有明确的结构性成因,不属于该文所谓的 "inherent differences between tasks"。引用其结论时必须区分这两层。

### 1.5 适用性判决

**直接适用**
- App C.1 的诊断器(见 §五-必做 1):这是全文唯一可直接落地的工程资产。
- App B 的"β/μ 异质 ⇒ 跨任务梯度不可比"结论,直接否定了我们用梯度幅度做课程 / 动态权重调度的想法。

**明确不适用 / 需反向解读**
- §4 的"长度无关"结论**不能照搬**。它成立的前提是 loss 在**整个 batch** 上做 token 平均;我们的口径是"每微批 token 平均后跨微批累加",在该口径下每个微批贡献**等额总权重**,与其内含多少条轨迹、多少 token 无关——一条 20k token 的 research 轨迹独占一个微批,与另一个装了 8 条 2k token executor 轨迹的微批拿到**相同的梯度总权重**,等价于把这条 research 轨迹按轨迹计上调了约 8×。这与该文假定的 length-invariance 方向相反,必须实测。

**不采纳**
- 梯度正比采样(§3.2)及其一切变体。

## 二、2607.07178 — EPPO: Entropy Pacing Policy Optimization for Multi-Task Agentic RL

NTU 生成式 AI 实验室 + 通义实验室(阿里),2026-07-08,18 页。
**三篇中与我们最贴的一篇:多轮 agentic、GRPO、Qwen 骨架,且 benchmark 含 ALFWorld。**

### 2.1 机理与证据(§4.1, §5.3)

现象命名 **exploration–exploitation pace mismatch**:简单任务过早坍缩到低熵、抑制难任务学习;难任务的探索性更新又把已收敛任务推回高熵。共享参数把两者耦合,表现为**跨任务熵曲线频繁交叉 + 训练末期熵尖峰**。
归因:GRPO 的**全局固定 clip ε 是任务无关的信赖域代理**,一个 ε 无法同时"给过度自信任务刹车"和"给欠探索任务放行"(§4.1 末)。

三个量化诊断(Fig 1c):

| 诊断量 | 定义 | AgentRL | EPPO |
|---|---|---|---|
| Crossover count ↓ | 任务两两熵序反转(符号翻转)事件计数,刻画共享参数耦合下的秩序不稳定 | 727 | 555 |
| Trend R² ↑ | 各任务熵对 **log t** 线性拟合的决定系数均值,作趋势一致性代理 | 0.107 | 0.443 |
| Late spike amplitude ↓ | 训练**最后 30%** 内最大向上熵跳变 | 0.351 | 0.154 |

### 2.2 算法(公式逐条抄录)

**(A) 熵追踪器**

- Eq(5) `H_i(t) = E_{(s_t, i)}[ −Σ_a π_θ(a|s_t, i)·log π_θ(a|s_t, i) ]` —— 任务 i 的策略熵。
- Eq(6) `H̄_i(t) = β·H̄_i(t−1) + (1−β)·H_i(t)` —— EMA 平滑,β 为衰减系数。
- Eq(7) `R_i(t) = H̄_i(t) / H_i(0)` —— **熵坍缩比**,除以各自初始熵后**无量纲**,使不同熵尺度的任务可比。

**(B) 进度调速器(Progress pacer)**

- Eq(8) `z_i(t) = ( R_i(t) − μ_R(t) ) / ( σ_R(t) + ε )`,其中 μ_R、σ_R 取自同一步全部 N 个任务的 `{R_j(t)}_{j=1..N}` —— **队列内标准化**,使调速依赖**相对进度**而非绝对熵。
- Eq(9) `s_i(t) = 1 + α·tanh(z_i(t))` , `ε_i(t) = ε₀·s_i(t)`,α ∈ (0,1) 为调速强度。因 tanh ∈ [−1,1],故 `s_i ∈ [1−α, 1+α]`,防止 clip 爆炸或消失。
  语义:坍缩过快(R_i 小、z_i < 0)→ ε_i < ε₀ 收紧;欠探索(z_i > 0)→ ε_i > ε₀ 放行。

**(C) 稳定性趋势约束**

- Eq(10) `ΔH̄_i(t) = H̄_i(t) − H̄_i(t−1)`
- Eq(11) `ε_i(t) ← ε_i(t) / ( 1 + ReLU(ΔH̄_i(t)) )` —— **单侧**惩罚,仅在熵上升时收紧。
- Eq(12) `L_i^EPPO(θ) = E[ min( ρ_{g,t}(θ)·A_t^i , clip(ρ_{g,t}(θ), 1−ε_i(t), 1+ε_i(t))·A_t^i ) ]`

**理论保证**(App D.1)
- **Prop 1(一致有界性)**:`(1−α)ε₀ ≤ ε_i(t) ≤ (1+α)ε₀` 对所有 i、所有 t 恒成立 —— clip 范围永不退化。证明:tanh 有界给出上下界,趋势约束的除数 `d_i(t) = 1 + ReLU(ΔH̄_i) ≥ 1` 只会进一步缩小。
- **Prop 2(趋势约束的稳定化)**:收缩比 `γ_i(t) = ε_i(t)/ε_i^paced(t)` 满足:(i) 熵不增时 γ=1(不额外约束正常收敛的任务);(ii) 熵增时 `γ_i = 1/(1+ΔH̄_i) < 1` 且 `∂γ_i/∂(ΔH̄_i) < 0`(熵升越猛收缩越强);(iii) 对 ΔH̄ 是 `(1+α)ε₀`-Lipschitz(响应平滑)。

**开销**:仅需 EMA 与任务级统计量的轻量记账,替换固定 clip 即可插入现有 GRPO 管线。

### 2.3 超参(§5.1 + App A.2)

核心三个:**ε₀ = 0.2、α = 0.4、β = 0.95**,并有硬夹紧 **ε_min = 0.15、ε_max = 0.3**。
> ⚠️ 注意:α=0.4 的 Prop 1 理论区间是 [0.12, 0.28],所以 ε_min=0.15 是比理论下界**更紧的人为地板**,ε_max=0.3 略高于理论上界。

训练细节(App A.2):Qwen2.5-3B-Instruct,AgentRL 基建,8×H20;700 步,128 prompts/batch,8 rollouts/prompt;AdamW lr 1e-5、weight decay 0;**loss 用 token-mean reduction,每微批上限 16,384 token**;dual clipping c=3.0;KL 惩罚系数 1e-4(对 ref model);**entropy bonus 系数 = 0**;rollout τ=0.8,每轮 ≤1024 token,最大上下文 8192,每 episode 20 轮;actor float32 / ref bfloat16 + gradient checkpointing;FSDP + Ray + NCCL,SGLang 推理,GPU 训推对半 + 额外 25% 给 cross-policy sampling,每 25 步同步。

奖励口径(App A.1):全部归一化到 [0,1];无原生 reward 的任务用 1/0 表示成功/失败;**异常终止罚 −0.2**;多任务按复制小数据集的方式**均匀采样**并交错。

### 2.5 局限

**自述**:只测了固定的任务组合;调速信号只用了 policy entropy(未探索其他 pacing signal);未结合动态任务采样。App C 自曝复现 AgentRL 与原论文有出入(改了 tool-call 参数解析与异步调度、硬件 8×H20 vs 原 16×H800、有效 batch 更小),**基线数字偏软**。

**我补充**:整套机制只作用于 **PPO/GRPO 的 clip**,对无重要性比、无 clip 的 OPD 与 SFT 项完全无效;且 §4.2 明确声明"不主张熵等价于学习进度",ε 只是**更新步幅闸门**。

### 2.6 适用性判决

**现象层直接适用**:我们担心的第 ③ 条(熵节奏失配:executor 近饱和已压熵、researcher 冷启动高熵)就是它定义的 pace mismatch,且它在 **ALFWorld** 上实测到了该现象。三个诊断量(crossover / trend R² vs log t / late spike amplitude)在 N=2 下依然有意义(crossover 退化为 `H_exec − H_res` 的符号翻转次数;后两个本就是单任务量),**可以照搬当监控**。

**⚠️ 控制器在 N=2 时数学退化,不能照搬**

Eq(8) 用队列 z-score,而**两个数的 z-score 恒为 ±1**:

```
两个值 a, b:  μ = (a+b)/2 ,  σ_pop = |a−b|/2
z_a = (a − μ)/σ = ((a−b)/2) / (|a−b|/2) = sign(a−b)     ⇒ z ∈ {+1, −1}
(若用样本标准差 n−1 口径:σ = |a−b|/√2 ⇒ z 恒为 ±1/√2 ≈ ±0.707)
```

**z 只剩符号、丢失全部幅度信息**,调速器退化为 bang-bang 开关:代入 α=0.4、ε₀=0.2 得
`s = 1 ± 0.4·tanh(1) = 1 ± 0.3046` ⇒ **ε 只能在 {0.139, 0.261} 两点间跳**;
样本 std 口径为 `1 ± 0.4·tanh(0.707) = 1 ± 0.2436` ⇒ ε ∈ {0.151, 0.249},且下界会被 ε_min=0.15 卡住。

EPPO 自己的数据也支持这个方向:三任务的消融差距(−0.7 / −1.5 pp)远小于五任务(−5.5 / −7.2 pp),作者归因"任务冲突更弱";外推到 N=2,机制可发挥空间最小。

**N=2 的正确实例化**(保留 Eq(5)(6)(7)(9)(10)(11) 与 Prop 1 夹紧,只换 Eq(8)):

用**绝对尺度的对数比**替代队列 z-score ——

```
z_exec(t) = ( 1 / (2·s₀) ) · log( R_exec(t) / R_res(t) )
z_res(t)  = − z_exec(t)
```

s₀ 为固定尺度常数(建议 **s₀ = 0.3**,即两角色坍缩比相差 e^0.3 ≈ 1.35 倍时 z ≈ ±0.5、tanh 已明显响应)。
这样保留了幅度、保留了 tanh 饱和与 Prop 1 的界,也保留了"两个角色对称一收一放"的语义。
Eq(10)(11) 的**趋势约束本身不依赖队列**(Prop 2 的证明全程只涉及单任务),可以单独挂在 researcher 项上当尖峰阻尼器,这一条无需任何改造。

## 三、2606.16771 — GD²PO: Mitigating Multi-Reward Conflicts via Group-Dynamic reward-Decoupled Policy Optimization

Qwen Business Unit(阿里)+ 人大 + 北大 + ETH Zürich + UZH + 港中文,2026-06-15,24 页。

### 3.1 机理与证据

问题定位在 **GDPO 的晚聚合**:GDPO 先按每个 reward 维度各自组内标准化

```
Eq(7)  A_n^i = ( r_n^i − Mean(r_1^i, …, r_G^i) ) / ( Std(r_1^i, …, r_G^i) + ε_adv )
Eq(8)  A_n^sum = Σ_{i=1..M} w_i · A_n^i
```

**一条 rollout 在某些维度正优势、另一些维度负优势时,加总会互相抵消**,使"高度冲突的 rollout"与"真正没信号的 rollout"在最终标量上不可区分,严重稀释有效学习信号(§1、§2 末)。

**证据**(§4.3 Fig 3):定义 **conflict ratio = reward 维度间优势符号不一致的 rollout 占比**。
- 跨 backbone、跨任务均非平凡;
- 三 reward 设置的早期冲突率高于两 reward(**维度越多越易分歧**);
- tool-calling 的冲突多集中在早期后快速下降,而 **helpfulness-safety 的冲突贯穿全程**(有用/无害的结构性张力);
- App C.2 Fig 5:**G=8 比 G=4 检出的冲突率更高**(更大的组暴露更多两两比较)。

**判别力验证**(App C.1 Table 6):按 SNR_n 排序,只用高一半 vs 只用低一半训练,**rollout 数量相同**:
Low-Conflict Half Correct **61.84** > GDPO 61.57 > High-Conflict Half **60.67**。数量与长度奖励都受控,故差距来自信号质量。

### 3.2 算法(公式逐条抄录)

**(A) 冲突感知过滤(§3.1)** —— 两种规则

- **硬过滤** Eq(10):`δ_hard(y_n) = 1{ Sign(A_n^i) = Sign(A_n^j) , ∀ i, j }`;**零优势视为中性**,不构成冲突。
- **SNR 过滤** Eq(11):

  ```
  SNR_n = | Σ_{i=1..M} w_i·A_n^i |  /  ( Σ_{i=1..M} | w_i·A_n^i |  +  ε )
  ```

  分子是抵消后的**净信号**,分母是各维度**潜在幅度之和**;方向一致时 → 1(constructive),严重抵消时 → 0(destructive interference dominated)。
  Eq(12):`δ_SNR(y_n) = 1{ SNR_n > τ }`。SNR 相比硬过滤能区分"轻微分歧"与"灾难性抵消"。
- Eq(13) 过滤后目标:`J^Naive = E[ (1/G)·Σ_n (1/|y_n|)·Σ_t γ_n^t( θ , δ(y_n)·Σ_i w_i A_n^i ) ]`

**(B) query 级重加权(§3.2)**

- Eq(14) `κ(x) = Σ_{n=1..G} δ(y_n)`(保留计数)
- 在 `E[z_n | δ=1] = μ_x`、`Var(z_n | δ=1) = σ_x²` 的独立性假设下(Eq 16),得
  Eq(17) `E[g_δ] = (κ/G)·μ_x` , `Var[g_δ] = (κ/G²)·σ_x²`
- 故信噪比 Eq(18):`|E[g_δ]| / sqrt(Var[g_δ]) = sqrt(κ(x)) · |μ_x| / σ_x` —— **随保留数单调上升**
- 于是取 Eq(19) `κ̂(x) = κ(x)/G`(保留比例)作为 query 可靠性的单调代理。

**(C) 完整目标** Eq(20):

```
J_GD²PO = E_{x, G(x)} [  (1/G) · κ̂(x) · Σ_{n=1..G} (1/|y_n|) · Σ_t γ_n^t( θ , δ(y_n)·Σ_i w_i A_n^i )  ]
```

Algorithm 1 顺序:采样 → 算 reward-wise 优势 A_n^m → 标量化 `A_n = Σ_m w^m A_n^m` → 算 δ_n、`Â_n = δ_n·A_n` → 算 `κ̂(x) = (1/G)Σδ_n` → 更新。

**开销**:只增加 M 维优势的符号 / 绝对值统计,可忽略。
⚠️ **执行顺序有硬要求**(App A.3):**rollout 级过滤必须在 batch-wise 归一化之前做**,被过滤的 rollout 在最终目标中优势为零、且不参与归一化统计。

### 3.3 超参(Table 5,App A.3)

batch 512 · mini batch 128 · max prompt 512(安全)/ 2048(工具)· max response 1024 · lr 1e-6 · **rollouts G=4** · rollout temp 0.7 / 1.0 · top-p 1.0 · GPU util 0.6 · epochs 1 / 30 · eval 每 10 步。
**verl 框架**,8×A800-80GB;工具调用单次 10–20h、helpfulness-safety 约 8h。所有 reward 等权 `w_i = 1`。工具调用结果报在 step 200、helpfulness-safety 报在 step 100。
τ 取值:tool-calling 三 reward 用 **τ=0.5**、helpfulness-safety 用 **τ=0.8**。

### 3.4 效果幅度与消融

- **Table 1 两 reward 工具调用**:GD²PO-Hard 相对各骨架最强基线的 Correct Acc 提升 **+1.50 / +1.31 / +1.74 pp**(Qwen2.5-1.5B 52.96、Qwen2.5-3B **62.88**、Llama3.1-8B **58.79**)。
- **Table 3 三 reward**:SNR 变体反超 Hard(1.5B Correct 56.01 vs 54.47;3B 60.97 vs 60.80;8B 62.75 vs 61.37)。**维度少时符号规则够用,维度多时需要连续度量。**
- **Table 2 helpfulness-safety**:Overall Avg,Llama3.2-3B 5.756(GRPO)→ **5.808**(Hard);Qwen2.5-7B 5.425 → **5.703**。Useful 与 Harmless **同向改善而非此消彼长**(Fig 2 训练曲线亦然)。
- **Table 4 拆解**(Qwen2.5-3B,correctness+length,SNR 用 τ=0.5):GDPO 61.57 → Hard w/o QR 62.51 → Hard **62.88**;SNR w/o QR 62.21 → SNR **62.78**。**过滤本身贡献主要增益,query 重加权再加约 +0.4 ~ +0.6 pp。**
- **Fig 4a 关键动态**:保留比例从早期 0.6–0.7 **在约 50–75 步后回升到 ~1.0** —— 该过滤基本是**训练早期的装置**,后期自动失活。
- **τ 敏感性**:三 reward 工具调用 τ=0.5 最好(Fig 4b);helpfulness-safety 上 τ 越大越好(Table 8:0.2→5.600 / 0.4→5.608 / 0.5→5.637 / 0.6→5.654 / **0.8→5.794**)。
- **App C.2 rollout 数**(helpfulness-safety, Qwen2.5-7B):GDPO G=4 → 5.600、Hard G=4 → **5.703**;GDPO G=8 → 5.698、Hard G=8 → **5.722**。两种 G 下过滤都有效。

### 3.5 局限

**自述**:τ 是固定超参,最优值随任务、reward 尺度、reward 组合、模型骨架而变,需要未来做**自适应阈值**(依在线训练动态、如 reward-wise 优势分布)。

**我补充**:
- **它处理的是"同一条 rollout 上多个 reward 维度"的冲突,不是多任务**——这是与我们场景最大的错配点;
- G=4 偏小,组内统计噪声大;
- 增益量级 1–2 pp;
- **对长度偏置毫无贡献**——其 Eq(5)/(13)/(20) 采用**逐序列 token 平均后组内等权**(每条 rollout 等权、与长度无关),且长度在它这里是一个 *reward 维度*(Eq 21:`r_len = min(|Words(Think(y))| / L_max, 1)`,L_max=512)而非梯度偏置来源。

### 3.6 适用性判决

**值得移植的是"冲突的可测化 + 冲突态下缩步",不是它的原始 rollout 过滤器。**

我们四项 loss 大部分作用在**不同样本**上(OPD / RL_exec 在 executor 轨迹、SFT 在 SFT 数据、RL_research 在 research 会话),真正发生"同一样本上多个信号打架"的只有一处:**executor 轨迹同时吃 OPD 和 RL_exec**。这一处可以精确移植:

对 executor rollout n 的 token t,定义两个带符号贡献:

```
a^RL_{n,t}  = w_rl  · Â_n
             (轨迹级优势广播到 token;PG 对被采样 token logit 的更新方向 ∝ Â_n·(1 − π_θ(y_t)),
              故符号 = sign(Â_n))

a^OPD_{n,t} = w_opd · ( p_teacher(y_t | ·) − π_θ(y_t | ·) )
             (前向 KL / CE 蒸馏对 logit v 的梯度为 (π_θ(v) − p_T(v)),
              最小化 ⇒ 更新方向为 (p_T(v) − π_θ(v));正号 = 要求抬升)
```

则 token 级(Eq 11 的 M=2 特例):

```
SNR_{n,t} = | a^RL_{n,t} + a^OPD_{n,t} |  /  ( |a^RL_{n,t}| + |a^OPD_{n,t}| + ε )
conflict_ratio = 符号不一致 token 的占比        (按 token 平均可得轨迹级 SNR)
```

两个量在现有 loss 里都已算出,**零额外前反传开销**。典型冲突形态很具体:**一条失败轨迹(Â < 0)上,teacher(policy + 经验文档前缀)恰好认可了那些导致失败的 token,于是 OPD 抬、RL 压。**

**不采纳其过滤器本身**:直接把冲突 token 的梯度置零会与 OPD 的 dense 性质冲突(OPD 的价值恰在于覆盖 RL 无信号的 token),且它自己的 Fig 4a 显示过滤在 50–75 步后就自动失活。
**采纳 κ̂ 的思想**(见 §五-必做 3、症状驱动 7)。

## 四、横向:三篇对"难度差异 ⇒ 部分任务无有效训练信号"分别怎么说

| 论文 | 对该问题的立场 | 给出的手段 |
|---|---|---|
| **2510.19178** | §4 承认极端准确率下 `A^π → 0`、期望梯度 → 0;但坚持**梯度幅度不单调于难度**,跨任务无一致规律 | **不给方案**,且**明确反对**按梯度/难度做任务重加权(§3.2 反证实验) |
| **EPPO** | 不处理组内退化;把"节奏差异"处理成**熵相位差**而非信号有无 | 间接手段两条:reward 全归一化到 [0,1] 且**异常终止罚 −0.2**(在全失败组里制造非零方差,天然破简并);任务复制后**均匀采样** |
| **GD²PO** | 明确引用 DAPO 的 Eq(9)(`0 < |{y_n : is_equivalent(a*, y_n)}| < G`)作为退化组的标准解 | 自身贡献是**软替代**:`κ̂(x) = κ/G` 把"证据不足的 query"降幅更新,而非丢弃重采样 |

### 方案是否冲突:不冲突,但有一处需要仲裁

三者作用在**不同层**:19178 管"别按幅度重加权"(约束条件)、EPPO 管信赖域 ε(步幅闸门)、GD²PO 管样本保留与 query 步幅缩放(信号纯度)。

EPPO 的 Table 1 恰好**佐证**了 19178 的警告——基于样本的 DCPO(29.9)和基于优势幅度的自适应裁剪 BAPO(44.4)都输给 AgentRL(51.6),而只调 ε 的 EPPO 赢(54.3);§5.2 原话是 "task-wise entropy pacing is more effective than sample or advantage clipping for reducing inter-task interference"。

**唯一的真冲突点**:researcher 项很可能**同时**是"欠探索"(EPPO ⇒ 放大 ε_res)和"低共识 / 高噪声"(GD²PO ⇒ 缩小 κ̂)。两个旋钮方向相反。
**仲裁规则**:**ε 决定单步允许走多远(信赖域),κ̂ 决定这一步该不该信(证据量)**;证据不足时以 κ̂ 优先 —— 即**先乘 κ̂ 再由 ε 限幅,不要用 ε 去补偿被 κ̂ 缩掉的步长**。

### 关于长度偏置的横向结论(直答关切)

**三篇都没有研究我们这个口径。**
- **19178** 用一句话把它假设掉("averaged over tokens … invariant to sequence length",§4),而它实际测的是 **batch 级** token 平均;
- **GD²PO** 用逐序列 token 平均(轨迹等权,与长度无关),长度只作为 reward 维度出现;
- **只有 EPPO 在工程上正面处理了** —— App A.2 的 "token-mean reduction, **capped at 16,384 tokens per micro-batch**"。

按 **token 预算**(而非按样本条数)切微批,能让各微批分母近似相等,从而使"每微批平均后累加" ≈ "全局 token 平均",偏置自然消失。**这是我们能拿到的唯一直接对症的工程做法。**

## 五、给 TRACE-OPD 的落地建议清单

### A. 必做(低成本、高确定性,且不改训练语义)

1. **接入 19178 的无偏平方梯度范数估计器,按 loss 项分别统计**(App C.1):微批对半 → `⟨ĝ₁, ĝ₂⟩` → EMA 0.95,**只算最后一个 transformer block**。
   *理由*:这是全场唯一能在不付 4 次反传代价下拿到 `w_opd·∇OPD / w_rl·∇RL_exec / w_sft·∇SFT / w_res·∇RL_research` 诚实幅度比的方法,且 App D.1 已验证末层是可靠代理。

2. **把 EPPO 的三个熵诊断量按 executor / researcher 两角色打点**(crossover 次数、熵对 log t 的 R²、后 30% 最大向上跳变)。
   *理由*:这三个量在 N=2 下不退化,且 EPPO 在 ALFWorld 上实测过,能把"熵节奏失配"从猜测变成读数。

3. **改为 token 预算切微批(参照 EPPO 的 16,384 token/微批上限),而非按轨迹条数切**。
   *理由*:当前"每微批 token 平均后跨微批累加"使每个微批贡献等额总权重,一条独占微批的 20k token research 轨迹会拿到与 8 条 executor 轨迹相同的总梯度权重(≈8× 超配);三篇里唯一对症的工程解就是这个 token cap。

4. **先用第 1 条的读数把 `w_opd / w_rl / w_sft / w_res` 校到量级可比,然后固定不动**。
   *理由*:19178 的 Table 1 / Table 3 证明按梯度幅度**动态**调度会降低平均性能(η 越低越差),但它同时证明了幅度差可达 15–33×,静态对齐初始量级是必要的、动态跟踪是有害的。

5. **executor 侧启用 DAPO 式动态采样(`0 < 正确数 < G`)**。
   *理由*:executor 已训练多步接近饱和,全对组占比会持续上升,这正是 DAPO 的设计场景;GD²PO §2 明确把它作为退化组的既有正解引用,与另两篇无冲突。

6. **executor 的 reward 加"异常终止 −0.2"式的分档**(EPPO App A.1)。
   *理由*:成本近零,能让"干净失败"与"崩溃 / 超轮次"在全失败组里产生非零组内方差,把一部分退化组救回。

### B. 症状驱动(先看第 1–2 条读数,命中症状再做)

7. **症状:researcher 组内 reward 方差长期接近 0(K=8 下游成功率全同)。做法:上 GD²PO 的 κ̂ 软降权(Eq 19),不上 DAPO 重采样。**
   *理由*:一条 research 轨迹要 8 次下游 rollout 才评得出分,丢弃重采样的代价是 executor 侧的 8 倍以上;κ̂ 用零额外采样换到"证据不足就少走一步"。

8. **症状:executor token 级 conflict ratio(§3.6 定义)持续高于 ~20%。做法:对冲突 token 按 SNR 降权(乘 SNR_{n,t}),不做硬置零。**
   *理由*:GD²PO App C.1 已验证 SNR 排序确有判别力(高低半 61.84 vs 60.67),但硬过滤会挖掉 OPD 在 RL 无信号区的覆盖作用;另 Table 3 显示维度增多 / 信号连续时 SNR 优于符号规则,我们这里 OPD 优势本就是连续量。

9. **症状:researcher 熵出现 EPPO 式后期尖峰(诊断 3 显著)。做法:只挂 Eq(10)(11) 的趋势约束到 RL_research 的 clip 上,`ε_res ← ε_res / (1 + ReLU(ΔH̄_res))`。**
   *理由*:Prop 2 的证明不依赖任务队列,单任务即成立,是三篇中唯一可以 N=1 使用的稳定器;且 EPPO Fig 4 展示了不加它时"熵微升 → 被放大 → 误判欠探索 → 再放松"的正反馈,与我们 researcher 长轨迹高噪声的处境高度同构。

10. **症状:诊断 1(crossover)显示两角色熵序反复反转。做法:实施 §2.6 的 N=2 改造版调速器** —— 保留 Eq(5)(6)(7)(9)(10)(11) 与 Prop 1 夹紧,把 Eq(8) 换成对数比 `z_exec = (1/(2s₀))·log(R_exec/R_res)`、s₀ ≈ 0.3;起始超参沿用 ε₀=0.2、α=0.4、β=0.95、硬夹紧 [0.15, 0.3],α 按 Table 5 在 0.2 / 0.4 / 0.6 里扫。
    *理由*:现象适用但 Eq(8) 在 N=2 数学退化为 ±1 的 bang-bang(推导见 §2.6),必须换掉才能保留幅度信息。

11. **仲裁规则(若 9/10 与 7 同时触发)**:**先乘 κ̂ 再由 ε 限幅**,不用 ε 去补偿 κ̂ 缩掉的步长。
    *理由*:两个旋钮在 researcher 上方向相反(欠探索要放大 ε、低共识要缩小 κ̂),需要一个固定优先级避免互相抵消。

### C. 不采纳

12. **不做梯度正比采样 / 任何按梯度幅度分配任务采样概率的课程。**
    *理由*:19178 Table 1 + Table 3 是直接反证 —— 三个骨架、两种任务组合、三档温度下平均性能一致劣于均匀采样。

13. **不用 |优势| 或 loss 值作为跨 loss 项的梯度幅度代理。**
    *理由*:19178 Fig 2 证明 |A| 只在任务内成立、跨任务失效,App B 给出了原因(各目标的 β、μ 不同);我们四项 loss 的形式差异比它们的任务差异更大。

14. **不照搬 EPPO 的 Eq(8) 队列 z-score。**
    *理由*:N=2 时 z 恒为 ±1,只剩符号,ε 退化为两点跳变(α=0.4、ε₀=0.2 ⇒ {0.139, 0.261}),失去调速本意。

15. **不把 19178 的"长度与梯度幅度无关"当作我们可以不管长度的依据。**
    *理由*:该结论的前提是 batch 级 token 平均;我们的每微批归一化恰好破坏这个前提(见必做 3),必须用必做 1 的估计器按长度分桶实测后再下结论。

16. **不采用 GD²PO 的硬过滤(Eq 10)作为主力规则。**
    *理由*:我们只有 2 个信号维度且其中 OPD 优势是连续量,符号规则过于粗暴;GD²PO 自己的 Table 3 也显示维度 / 连续性增加时 SNR 优于 Hard。

## 六、一句话总纲

**19178 给我们度量工具和一条禁令**(测得准、别按幅度调度),**EPPO 给我们现象命名、诊断三件套和一个需要改造的控制器**(N=2 要换掉队列 z-score),**GD²PO 给我们冲突的可测化和"证据不足就少走一步"的软降权**(κ̂,而非它的硬过滤)。三者不冲突,唯一需要仲裁的是 researcher 上 ε 放大与 κ̂ 缩小的方向相反。
